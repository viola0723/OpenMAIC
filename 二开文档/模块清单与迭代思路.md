## 跨模块议题（长期迭代）

### 议题：生成图片 ↔ 课件版式适配（2026-09-05 V 立，课程生成质量）

**现象**：AI 配图进课件后比例错配——LLM 在 DSL 里按设想画图片框（常 16:9），而 gpt-image-2 只有三档固定尺寸（1024²/1536×1024/1024×1536，16:9 归一为 3:2），框图宽高比系统性不一致。

**当前处置（已落地）**：渲染端三条路径全部 `objectFit:'contain'` 保底（完整可见、不裁不拉、余量透明）：主画布/编辑面 `components/slide-renderer/.../ImageElement` ×2 + 缩略图 `packages/@openmaic/renderer`（改该包必须 `pnpm --filter @openmaic/renderer build`）。裁剪态（clip.range）保持 fill。

**迭代方向（按优先级）**：
1. **媒体生成阶段按元素框真实宽高比选图尺寸**——placeholder 带 elementId，场景生成后媒体阶段可查到框的宽高，选最接近的图档，余量最小化（首选，改动集中在 `classroom-media-generation.ts`）
2. DSL 框随真实图宽高比自适应（绝对定位画布有重排风险，谨慎）
3. PPTX 导出链路（`use-export-pptx.ts`）的图片铺设检查是否有同款问题（A 路线展品化时一并验）
4. 若哪天接了支持任意宽高的生图渠道（如即梦 CLI 的 --width/--height），适配空间更大

### 议题：互动场景视口宽度（2026-09-05 V 立，视觉一致性）

**现象**：interactive 场景吃满整个画布（`canvas-area.tsx:307` StageViewport 对 interactive 用 `h-full w-full`，slide 锁 `aspect-[16/9]`——上游刻意设计，仿真要大操作空间），与 slide 页切换时视觉跳跃，超宽带鱼屏没有信息增量（傅里叶课第 2 页波形叠加器实例）。

**候选**：①保持现状 ②互动也锁 16:9 ③折中：加温和上限（如最宽 21:9 / max-width 居中）。K 倾向③。待 V 拍板后排期。

## 七、后端系统模块

**两套生成路径 + 两套讨论路径**是理解全局的关键：
- 生成 A（一键/服务端 job）：`POST /api/generate-classroom` → 后台流水线 → `data/classrooms/`（首课走的这条）
- 生成 B（浏览器分步驱动）：`use-scene-generator.ts` 逐调 `/api/generate/scene-*`
- 讨论 A（主路径，stateless）：`POST /api/chat` + 前端驱动循环
- 讨论 B（Pi，实验性，flag 门控）：`POST /api/chat/pi` 服务端 agent loop

### 7.1 课程生成流水线（路径 A）

- 入口 `app/api/generate-classroom/route.ts:44`（`after()` 异步，`maxDuration=30`），轮询 `[jobId]/route.ts`
- 主流水线 `lib/server/classroom-generation.ts:176` `generateClassroom()`：解析模型 → 可选搜索（`search-query-builder.ts`）→ 场景大纲 → Agent 阵容（`generate` 模式 LLM 出人设 / 否则 `DEFAULT_AGENTS` 默认阵容，`lib/orchestration/registry/store.ts:47`）→ 逐场景内容+教学动作（带重试）→ 媒体阶段（图/视频并行，`classroom-media-generation.ts:85`）→ TTS 阶段（长语音切段，`:251`）→ 落盘 `data/classrooms/<id>.json`
