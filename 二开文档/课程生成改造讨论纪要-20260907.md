# 课程生成改造讨论纪要（2026-09-06 ~ 09-07）

> 定位：与《模块清单与迭代思路.md》《课程生成链路调研.md》并列。调研是「现状地图」，本文是「改造方向的可能性地图」——
> **V 定调：讨论产出是可能性与大概要点，不是施工约束；实施时逐条重新评估**。
> 技术细节（file:line）一律回查《课程生成链路调研.md》，本文不重复行号。

## 0. 讨论原则（V 定）

1. **质量优先，成本后置**：先求质量，在保证质量的基础上才谈成本
2. **不靠一条固定产品线完成所有效果**：一次性管线出初稿，**二次迭代出精品**——迭代入口是质量体系的主干
3. **评测分工**：机器做「确定是错」的客观初筛，**好坏终审归 V**；生成完附体检报告，V 带报告审重点
4. **游戏化挂起**：当前仍是开发课堂不是开发游戏；游戏化只留地基记录，细节不急

## 1. 配图质量（上次图片压扁 bug 的根治）

**问题本质**：不只是比例——是「写图 prompt 的不知展示尺寸、摆框的不知图内容、生图的不知框，成品无人校验」的全开环。
比例错配的根源已查明：openmaic 把 gpt-image-2 请求归一到三档是**误诊**（1024×576 被拒的真实原因是总像素低于 655,360 下限；
gpt-image-2 实际支持任意尺寸：边 ≤3840、16 的倍数、比例 ≤3:1、总像素 65.5万–829万——1280×720 即合法 16:9，待用中转通道冒烟坐实）。

**配图策略矩阵**（三路线合并）：

| 图的用途 | 路线 |
|---|---|
| 信息图 hero（全幅核心知识图） | 即梦 5.0Pro：2k/4k 大图 + prompt 控制内容区域位置（`<bbox>`/`<point>` 坐标级能力）→ 按框裁切合并 |
| 装饰贴纸（icon/插图） | **gpt-image-2 透明背景**（我们生图阵容独家，已实测真 RGBA）——无框融入版式，比例问题直接消失；注意光效材质会半透明，prompt 补「主体实心」 |
| 照片/横幅 | 任意 provider 直通精确尺寸（修掉归一化误诊后） |

**配套机制**：①`mediaGenerations` 加 `role` 用途字段（hero/illustration/icon），大纲声明 → 内容排版纪律 → 生图密度指导三层联动；
②框先图后：场景内容生成后框已知，把展示尺寸/密度写进生图 prompt；③VLM 校验环（图内文字可读性/主体完整性/主题匹配，不合格重生）。
**实施注意**：openmaic 的 openai-image 适配层未暴露 `background` 参数，需扩。

## 2. 全局优化 agent + 课程迭代入口（同一台机器，两个触发器）

现状坐实：管线里没有任何环节俯瞰全课（逐场景生成只带上一场景逐字稿），全局性问题（风格漂移/术语不一/旁白断裂/布局失衡/图文错配/事实错误）连被发现的机会都没有。

**设计共识**：
- 同一套机制（编辑工具 + patch 应用 + 预览确认闸），两个触发器：管线内自动跑 = **polish 阶段**；事后指令驱动 = **迭代入口**
- 先做迭代入口（价值即时、风险可控、每次迭代攒真实测试用例），回头装进管线当 polish 阶段
- 插入点两道：场景全部生成后、媒体/TTS **之前**（文字层：旁白连贯/术语统一/布局修正——必须在 TTS 前否则音频返工）；媒体之后（视觉层：图文匹配，可看图）
- **B 路径迭代入口**是关键缺口：工作台 MAIC Agent 已是完整雏形（generate_scene/patch_stage/edit_deck 工具 + 快照回滚），但绑 Postgres 文档库，文件课够不着。补法形如 `POST /api/classroom/<id>/iterate {instruction}`，服务端复用工作台工具集改课堂 JSON——skill 出课流程升级为「生成 → 审视 → 迭代 → 再审视」闭环，全程无需浏览器
- patch 先预览确认再应用（玩家审阅闸，修仙 demo 经验同款）
- widget 冒烟（playwright 无头渲染抓 JS 错误 + 截图给 VLM）收编进校验环，不必塞进一次性管线

## 3. 模板自定义能力（修仙小课堂这样造）

三层机制：**大纲模式**（已有标准/interactive/task-engine 三先例，修仙模板照抄范式：开场剧情→剑理讲解→招式演示→弟子试炼→师父点评；代码只需模板文件+分发点加分支）；
**角色阵容**（agent-profiles prompt 换成「修仙选角导演」，师父/师妹/师弟各带 voiceDesign 音色配方）；
**视觉语言风格**（Stage.style + 生图风格词注入，直接吃修仙世界设定库/素材库的现成资产）。

## 4. 运行时模型分层（脑/嘴分工）

- 现状：所有 NPC + director 共享一个模型（`/api/chat` 整轮只解析一次），角色差异纯靠 prompt 人设；每轮请求历史全喂 + 状态压缩摘要
- **脑/嘴分层**（照抄修仙 demo 范式）：director/结构化动作 = 脑（JSON 能力模型）；NPC 措辞 = 嘴（**CharGLM-4**，纯文本、8k 无记忆、一答 ~0.8s）
- CharGLM 接入要点：给它「文本专用模式」（allowedActions 清空、prompt 不提动作契约——解析器本来就有纯文本降级兜底，零改动可跑通）；
  prompt 走紧凑装配路径（人设卡+场景摘要+当前问题），绕开全量历史；模型目录加 `charglm-4`（同 paas v4 端点同 GLM key，配置级）
- per-NPC 分模型需小手术：`AgentConfig` 加 model 字段 + agent_generate 节点内按 agent 解析
- 提醒：需要白板/教鞭配合的回答切回大模型 NPC（director 按问题类型选角）；记忆穿帮风险读 `修仙demo/经验参考/eluvien-ai-rpg-架构经验.md`（首坑）

## 5. 交互顺畅度三层方案

1. **讨论剧本化**：课件里的 discussion 动作目前是裸触发（只有 topic/prompt，台词全现场即兴）——生成期加「讨论剧本」阶段，大模型预写逐句台词 + 预制 TTS，运行时直接播；玩家插话才切 live，话落切回剧本
2. **live 部分接流式 TTS**：openmaic 全链路非流式是课堂停顿感根因（已登记 `大模型登记/语音/minimax.md`）；MiniMax `t2a_v2` 有 `stream:true` SSE 分片，腾讯云有 WSS 流式——能力俱在只差接
3. **预测性预取**：翻到场景 N 时后台预制 N+1 的开场白/高概率讨论

## 6. 音色机制澄清（B 路径的真实缺口）

一门课两套声音来源：**预制旁白**（B 路径单音色 female-yujie）+ **现场讨论**（运行时确定性轮转兜底，所以 V 听到的多音色是真的但是撞大运分的）。
改造点：①旁白按角色分音色；②生成期按人设选角配音（A 路径 voiceConfig 绑定链接到 B）；轮转兜底留作备胎。
**音色二期可调**：voiceConfig 存在课程文档里非终身绑定，改绑+重配 TTS 即可；整课批量重配无现成按钮但机制简单（遍历 speech action 重跑）。

## 7. 内容正确性校验

**原则：不是 LLM 自问自答，而是抽断言 → 对照外部权威源 → 标注存疑。**

| 校验源 | 管什么 | 现状 |
|---|---|---|
| **TapXWorld/ChinaTextbook**（GitHub，全学段教材，73k star） | 纯收藏登记，**不当检索源**（V 定：模型自带知识 + 搜索 + 权威数据源足矣） | tools/README 有登记 |
| kimi-datasource MCP | 数据型事实（统计局/国标 GB/法律/WHO/FAO/OECD） | 插件已挂载 |
| AnySearch academic 域 | 论文/学术断言 | 已接入管线 researching 阶段 |
| Kimi 内置搜索 + AnySearch 通用 | 时效事实、多源交叉 | 现成 |

三层落点：researching 多源对照 → polish 的 fact-check pass（标存疑不擅改）→ 迭代期复审。虚构内容（修仙课）对照源换成自家设定库，机制相同。

## 8. 中文排版与评测

- **排版**：调研开源 PPT/设计 skill 的纪律转写进 `slide-content` 模板与 snippets（标点避头尾/中西文混排/字号阶梯/每点字数）。原料已入库：`tools/guizang-ppt-skill`（双视觉系统）、`tools/emilkowalski-skills`（apple-design 审美约束，专治 AI 味）等，择机走 `调研/` 正式提炼成《课件排版规范》
- **评测**：机器初筛客观缺陷（JSON 合法/元素溢出重叠/KaTeX 渲染/字数/事实存疑标注）→ 体检报告 → **V 终审**；`eval/` 目录作回归基准防越改越退

## 9. A/B 路径策略（V 曾困惑，已澄清）

**不二选一，「改内核 + 补 B」**：模板/比例直通/校验环/polish 全改在共享内核 `@openmaic/generation` 包，A/B 同时受益；
B 只补两处简配——音色绑定链 + iterate 迭代入口。A 路径保持手工精做台（大纲审改/卡牌揭晓/即时编辑），B 路径管批量自动出课。

## 10. 游戏化挂账（只留地基，细节挂起）

- 课程 ≈ 场景序列 + NPC 群（agent）+ 玩家（USER 路由），骨架已是七成游戏引擎；每场景可单独配 NPC 阵容（Scene.multiAgent）
- 唯一硬核缺口：**分支机制**（19 种动作无 goto/条件跳转）；其次是玩家状态/存档
- **widget → 宿主事件回报通道**是游戏化地基（现在通信单向：宿主→widget 四指令，widget→宿主只有错误上报；定义 WIDGET_EVENT 即可通）
- 游戏化一旦走，B 路线活后端从候选变必需
