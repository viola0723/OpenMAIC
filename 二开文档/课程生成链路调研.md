## 0. 最重要的认知修正

**`lib/orchestration/` 不是课程生成的编排层。** 它是「上课时」实时多智能体讨论的 LangGraph（director 选谁发言 → agent 流式产出「说话+动作」，服务 `app/api/chat/route.ts:132`），与课程生成无调用关系。

真正的课程生成核心在三处：

| 层 | 位置 | 角色 |
|---|---|---|
| **生成内核** | `packages/@openmaic/generation/`（独立 workspace 包） | 大纲/内容/动作三个生成器 + JSON 修复 + 重试，**所有 LLM 生成逻辑唯一真源** |
| 一键管线 | `lib/server/classroom-generation.ts` | 服务端 job 编排（skill/脚本用，我们的出课路径） |
| 分步管线 | `app/api/generate/*` + `lib/hooks/use-scene-generator.ts` | 浏览器 UI 主路径（generation-preview 驾驶舱） |

## 1. 三条生成路径，一个共享内核

| 路径 | 入口 | 编排者 | 存储 | 消费方 |
|---|---|---|---|---|
| **A 浏览器分步管线**（UI 主路径） | 首页 `app/page.tsx:571` → sessionStorage → `/generation-preview` | 前端 `use-scene-generator.ts:627` | IndexedDB（Dexie）/ Postgres | 浏览器 |
| **B 一键 job 管线**（我们出课用的） | `POST /api/generate-classroom` | 服务端 `classroom-generation.ts:176` | `data/classrooms/*.json` 纯文件 | skill/脚本（**无浏览器 UI 消费轮询端点**） |
| **C Pro 工作台 agent** | `POST /api/agent/sessions`（SSE） | 服务端 agent runtime 工具（`lib/server/agent-runtime/generation-tools.ts`） | Postgres 文档库 | 工作台 |

三条路径**都调同一个 `@openmaic/generation` 包的同一组函数**（`generateSceneOutlinesFromRequirements` / `generateSceneContent` / `generateSceneActions` / `buildCompleteScene` / `applyOutlineFallbacks` / `withGenerationRetry`），产出物 Scene/Stage 格式完全一致。差异在资源处理（见 §7）。

**两套存储互不相通**：
- B：纯文件。`data/classrooms/<id>.json` 单文件（`{id, stage, scenes, createdAt}`，无 manifest.json）+ `<id>/media/`、`<id>/audio/` 子目录；静态服务走 `GET /api/classroom-media/<id>/...`（含路径遍历防护、Range 支持）
- A/C：Dexie（浏览器默认）或 Postgres 文档库（`/api/stages`、`/api/stage-meta`、`/api/persistence`，需 `DATABASE_URL`，未配置一律 404）
- 课堂页加载两级回退：先 IndexedDB，miss 才 `GET /api/classroom?id=`（`lib/classroom/load-classroom.ts:256`）；首页「最近学习」只读 IndexedDB（API 管线出的课需先访问一次课堂链接才进课程库——已录锚点）

## 2. 生成阶段分解（一键管线主线）

`generateClassroom`（`lib/server/classroom-generation.ts:176-738`）：

```
initializing(5%) → researching(10%,可选web搜索) → generating_outlines(15-30%)
→ [agent profiles，agentMode='generate' 时] → generating_scenes(30-90%,逐场景)
→ generating_media(90%,可选) → generating_tts(94%,可选) → persisting(98%)
```

LLM 调用粒度（与实测 ~9.8 万 token/课、4.5 分钟自洽）：

1. **搜索改写**（可选）：整课 1 次，`web-search-query-rewrite` 模板，可路由便宜模型
2. **大纲：整课 1 次** → `{languageDirective, courseTitle, outlines[]}`（包内 `outline-generator.ts:120-183`）
3. **角色阵容：整课 1 次**（可选；一键管线是简化版，只出 `{name, role, persona}`，见 §7 分化）
4. **逐场景：每场景恰好 2 次调用** = 内容 1 次（`scene-generator.ts:227-314`，按 type 分派 slide:602 / quiz:854 / interactive→widget:1117 / pbl:988）+ 动作 1 次（`:1608-1761`，产出 speech + spotlight/laser/widget_* 动作序列）
5. 7 场景课 = 1 大纲 + 14 场景 + 重试余量 ≈ 15+ 次 LLM 调用

**场景间上下文传递很朴素**：只传①本场景 outline ②全课标题列表 ③**上一场景的完整逐字稿**（`previousSpeeches`，不做摘要，见 `pipeline-types.ts:18-23` 与 `scene-actions/route.ts:139-147`）。这是语气连贯的唯一机制，也是 actions 必须串行的原因。

**并行度现状**：
- 一键管线：**完全串行** for 循环（`classroom-generation.ts:558`）
- 分步管线：content 可有界并行（`PARALLEL_SCENE_CONCURRENCY`，**默认 0 = 关**，`use-scene-generator.ts:686-696`；`lazyBoundedMap` 预热后续场景但按序消费 :727-774），actions + TTS 严格串行（:802-871）；媒体生成与内容/动作并行点火（:670-674）

## 3. job 机制（B 路径）详解与硬缺口

入口 `app/api/generate-classroom/route.ts:14-60`：收 `{requirement*, pdfContent?, enableWebSearch?, enableImageGeneration?, enableVideoGeneration?, enableTTS?, agentMode}` → `nanoid(10)` jobId → 写 `data/classroom-jobs/<jobId>.json`（queued）→ `after()` 异步跑 → **202 返回 `{jobId, pollUrl, pollIntervalMs:5000}`**。

- **状态机**：`queued → running → succeeded/failed`（`classroom-job-store.ts:15`）；step 枚举 `initializing/researching/generating_outlines/generating_scenes/generating_media/generating_tts/persisting/completed`（`classroom-generation.ts:62-70`）
- **存储**：每 job 一个 JSON 文件，tmp+rename 原子写；进程内 `runningJobs: Map` 只防同 jobId 重复启动（`classroom-job-runner.ts:11`）
- **轮询**：`GET /api/generate-classroom/[jobId]` 返回全量快照（step/progress/message/scenesGenerated/totalScenes/result/error/done），**无 SSE**；stale 兜底 = running 且 30 分钟无更新就地判死（`job-store.ts:76-94`）
- **进度消息**：人类可读文本，如 `Generating scene 3/7: xxx`、`Retrying scene 2/7 content (2/6)`；进度刻度 5→10→15/30→逐场景线性插值 30-90→90→94→98→100
- **重试**：`withGenerationRetry`（`packages/@openmaic/generation/src/generation-retry.ts:177-233`）默认 5 次、指数退避 1s→16s+20% 抖动、408/409/425/429/5xx/网络错误可重试；内容生成对「返回 null」也重试（`classroom-generation.ts:615`）
- **降级而非失败**：场景重试耗尽 → `continue` 跳过该场景（:623-626）；媒体/TTS 阶段整体 try/catch 只 warn；**全部场景失败**才抛错置 failed（:662-664）

**硬缺口（改造候选）**：
1. **无取消机制**：`[jobId]` 路由只有 GET；`withGenerationRetry` 支持 AbortSignal 但管线从未传入；HTTP 断连杀不掉 `after()` 里的 job
2. **无断点续传**：场景数据全程在内存（`createInMemoryStore` :89-114），进程重启 = 从头来过
3. **无并发上限无队列**：「一次一个」只是 skill 侧客户端纪律
4. `maxDuration = 30` 只约束请求本体，自托管 Node 下 `after()` 不受限（serverless 部署需注意）

## 4. 提示词体系（两层，改 markdown 即生效）

| 层 | 位置 | 内容 |
|---|---|---|
| 生成包 | `packages/@openmaic/generation/templates/`（13 模板）+ `prompts-pbl/`（3） | 课程生成主链全部模板 |
| App 层 | `lib/prompts/templates/`（8 模板） | 运行时课堂讨论 + interactive/task-engine 两种大纲模式 |

**loader**（`lib/prompts/loader.ts:131-157`，生成包内同构）：三种占位符按序处理——`{{snippet:name}}` 片段拼接（缺失抛错）→ `{{#if cond}}` 条件块（不嵌套）→ `{{var}}` 变量插值（**未知变量静默透传**，靠 `tests/prompts/templates.test.ts` 断言无残留 `{{}}` 兜底）。**无缓存**，`fs.readFileSync` 每次读盘，改模板即时生效。

**无 locale 机制**：模板是英文写的；课程语言靠大纲模板 "Language Inference" 决策节让 LLM 产出 `languageDirective` 字段（`requirements-to-outlines/system.md:17-56`），后续所有内容/动作模板接 `{{languageDirective}}` 变量接力。

**生成一门课用到的模板链**：
1. （可选）`web-search-query-rewrite`
2. 大纲：`requirements-to-outlines`（标准模式；interactive/task-engine 模式换 app 层对应模板，由 `scene-outlines-stream/route.ts:432-447` 分派）
3. （可选）角色阵容：**硬编码 TS 字符串 prompt**（`classroom-generation.ts:124-174`），不是 markdown 模板
4. 逐场景内容：`slide-content`（937 行，全元素契约）/ `quiz-content` / 按 widgetType 路由 6 个 `*-content`（simulation/diagram/code/game/visualization3d/procedural-skill）/ PBL 走 `prompts-pbl/`
5. 逐场景动作：`slide-actions` / `quiz-actions` / `interactive-actions` / `pbl-actions`

**结构化输出全靠 prompt 内 JSON 契约 + 宽容解析，不用 zod/JSON mode**（唯一例外：PBL v2 planner 用 AI SDK tool calling + zod inputSchema）。容错链：剥 `<think>` → code block 提取/括号配对扫描 → 四层修复（LaTeX 转义/补截断括号/`jsonrepair` 库/清控制字符，`json-repair.ts:177-277`）→ 大纲 fallback 降级（interactive 缺 widget 配置→slide、PBL 缺配置→slide 等，`outline-generator.ts:205-233`）→ 动作解析失败用模板化默认动作兜底（`scene-generator.ts:1877+`）→ 字段级清洗（`normalizeElement`/`fixElementDefaults`/KaTeX 预渲染）。

## 7. 媒体管线

**任务来源是声明式的**：大纲 LLM 直接产出 `mediaGenerations:[{type, prompt, elementId, aspectRatio?, style?}]`（教学见 `snippets/image-instructions.md`，「确实增强内容才加」）；占位符 `gen_img_N`/`gen_vid_N` 被大纲路由改写为全局唯一 `gen_img_<nanoid8>`；内容 LLM 被告知「用这些 id 当 src、保持声明宽高比」（`scene-generator.ts:676-702`），占位符原样留在元素 src 里（`resolveImageIds` :355-413），渲染层 `resolveMediaRef` 状态机（pending 骨架/done URL/failed 重试钮）渐进回填。

**图像尺寸链**：outline 的 `aspectRatio`（LLM 自选，默认 16:9）→ `resolveImageSize`（`lib/server/image-sizing.ts:66-125`）→ 1024 基准 → `IMAGE_MIN_PIXELS` 面积下限放大 → **gpt-image-2 归一三档**（1024²/1536×1024/1024×1536，这就是 3:2 由来）→ 强制 quality=low。
**挂账确认未解**：元素框真实宽高由内容 LLM 独立决定，但没有任何代码把框宽高回填进生图参数；`mediaRetryTarget`（`media-orchestrator.ts:116-126`）已带 elementId/sceneId/slideId 定位能力，改造落点现成。

**TTS 链**：文本 = 动作阶段 speech action 的 `text` 字段；**一条 action 一个 mp3**（仅 glm-tts 有 1024 字上限需拆，MiniMax 不拆）；id 规则 `tts_s{sceneOrder}_{actionId}`；MiniMax 默认 `speech-2.8-hd`、默认音色 `female-yujie`、32kHz/128kbps/mp3。
**音色解析三层**：agent 持久化 voiceConfig 绑定 → 全局设置 → `resolveDeterministicFallbackVoice`（`voice-resolver.ts:158-173`：第一个已启用 provider，音色 `index % voices.length` 轮转，narrator 固定 index=0，Qwen 克隆音排除）。

**两条路径的媒体/TTS 分化（改造重点注意）**：

| | A 浏览器分步 | B 一键 job |
|---|---|---|
| 图/视频 | 前端 orchestrator 后台并行点火、**严格串行**派发、无自动重试、失败持久化 IndexedDB；产物存 Dexie `mediaFiles`（主键 `stageId:elementId`） | 全部场景完后统一跑：图串行+视频串行、两路并行、失败只 warn；产物写盘 `<id>/media/`，**占位符直接替换成服务 URL** |
| TTS | **内联阻塞**场景完成（失败整场景回滚暂停）；音色绑定链完整 | 统一阶段跑；**全员共用一个默认音色**（`classroom-media-generation.ts:277`），VoxCPM auto 跳过 |
| 角色 | `agent-profiles` 完整版：voiceConfig + voiceDesign + avatar + color | 简化版：只出 name/role/persona，头像/颜色默认循环补齐（:537-545） |

**视频**：6 家 provider 全部 submit→poll（共用 `runPolledTask`）；**默认关闭**（`videoGenerationEnabled=false`），提示词侧也劝 LLM 少用（慢，1-2 分钟/条）。ComfyUI 仅图像。

**资产管理**：ref 三类（占位符/池分配 id/具体地址）；去重靠引用计数 + 独占所有权证明（`proveExclusiveAssetOwnership`，不满足就 fork 新 id）；**回收唯一入口是整课删除**（编辑产生的「有界过渡垃圾」是设计选择，池字节回收未接线）；课堂 ZIP 的 manifest.json 由前端 `buildClassroomExportZip` 生成（`enumerateAssetManifest` 只收被引用 ref，孤儿不进包）。

## 8. 数据模型（`packages/@openmaic/dsl/src/`）

- **`SceneType` 只有四种：slide / quiz / interactive / pbl**（`stage.ts:22-30`）——没有 whiteboard 场景类型；白板是场景级 `whiteboards?: Slide[]` + `wb_*` 动作的叠加层
- **Stage**（`stage.ts:141-174`）：`{id, name, languageDirective?, whiteboard?, videoManifest?, agentIds?, generatedAgentConfigs?, interactiveMode?, taskEngineMode?}`；**Stage 不内嵌 scenes**，Scene 靠 `stageId` 回指
- **Scene**（`stage.ts:228-283`）：`{id, stageId, title, order, actions[], whiteboards?, multiAgent?, content}`，type 与 content 判别绑定
- **四种 content**：slide→`{canvas: Slide{viewportSize, theme, elements: PPTElement[10种], background?, animations?}}`；quiz→`{questions[]}`（single/multiple/short_answer）；interactive→`{html, widgetType(6型), widgetConfig}`——**完整 HTML 文档，iframe srcDoc 渲染**（资源包能独立玩的原因）；pbl→`{projectV2}`
- **旁白 = `SpeechAction{text, audioId}`**（`action.ts:47-62`）：文本即字幕，音频是资产引用；动作共 19 种（spotlight/laser/speech/wb_*/play_video/discussion/widget_*），**本身不带时间戳**
- **计时语义单一真源在 `lib/choreography/`**：播放引擎与视频导出共享（防两边漂移）；fire-and-forget 仅 spotlight/laser，其余全阻塞；speech 时长优先真实音频时长，无音频按 CJK 150ms/字、英文 240ms/词估算（`timing.ts:113-120`）
- **角色 `GeneratedAgentConfig`**（`stage.ts:112-124`）：随文档持久化，含 voiceConfig + voiceDesign 三层配方，导出/导入不丢

## 9. 运行时编排与导出（相邻模块，简记）

- **运行时课堂讨论**：`lib/orchestration/` LangGraph 两节点（director → agent_generate），**单轮契约**——每个 HTTP 请求最多一轮，多 agent 讨论靠客户端串行化驱动；状态全随请求携带，服务端无状态。上下文压缩体系发达（最近 10 条×200 字摘要、元素单行摘要、白板账本重放、代码块 1200 字符共享预算等）
- **导出**（课堂页 Header 菜单）：PPTX（自建 pptxgenjs fork，LaTeX→OMML）/ **教学资源包 ZIP = PPTX + 自包含互动 HTML**（`inlineHtmlAssets` `lib/export/inline-assets.ts:495`：外链抓取→CSS 递归内联→script 变 data:URI→importmap 内联；A 路线产物成立的依据）/ 课堂 ZIP（manifest.json + 资产，仅迁移用）/ 演讲稿 MD/DOCX / MP4（Hyperframes 项目 ZIP → render-service headless Chromium 逐帧 + FFmpeg）
